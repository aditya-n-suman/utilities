Read this first, then `README.md` (install, permissions, privacy), `SETUP.md` (manual checks, release) and `design/Playlist Bridge Extension.dc.html` (UI spec). The web app's docs

## Goal
The web app's full functionality with **no backend, no API keys and no quotas**:
- Spotify: public embed page + web-player GraphQL, called from the extension.
- YouTube: internal YouTube Music / YouTube search APIs.
- Save: the user's own YouTube session (SAPISIDHASH), not Google OAuth.

## Verified end to end (Chromium, headless, no backend)
The 150-track "All Out 80s" playlist was matched in about 30 s (150 found, 6 to review), then: review, swap, manual search,
remove, reload → "Pick up where you left off" → resume (edits kept), links (50/50/49), CSV, missing-playlist error
→ paste fallback, and the "Convert to YouTube" button on a Spotify playlist page (opens the app and starts converting;
re-attaches after in-app navigation). No console errors. Repeat with `./instruction.sh e2e` (`tests/e2e/e2e.py`).

## Engine (src/engine)
- `sources/`: Spotify embed + pathfinder paging + query-hash recovery + paste/CSV
- `youtube/innertube.ts`: YouTube Music / YouTube search requests and parsers (videos checked against ytmusicapi output)
- `youtube/search.ts`: search order songs → videos → youtube.com, breaker, retries (port of search.py)
- `youtube/matcher.ts`, `fuzz.ts`: exact port of the Python matcher
- `jobs.ts`: job runner (port of jobs.py), same events as the web app's SSE; persists a resume snapshot
- `cache.ts` / `store.ts`: IndexedDB match cache (30 days) and the "current conversion" slot (7 days)
- `report.ts`: temporary links (50 per link) and the CSV report
- Searches send no cookies (`credentials: "omit"`). Only Save uses the YouTube session: the SAPISID cookie plus
  `Authorization: SAPISIDHASH <ts>_<sha1(ts SAPISID origin)>` (same as ytmusicapi). Saving creates the playlist with
  the first 50 videos, then adds 50 at a time (`browse/edit_playlist`); a failed batch returns a partial save, and
  "Add the rest" continues the same playlist (`Job.saveState`).

## Matcher parity (keep it)
`matcher.ts` is a line-by-line port of `apps/spotify-to-youtube/backend/app/youtube/matcher.py`; `fuzz.ts` ports
rapidfuzz's `ratio`/`partial_ratio`/`token_sort_ratio`/`token_set_ratio`. `tests/unit/golden.test.ts` requires identical
raw scores (1e-12), displayed scores and ranking for 58 tracks / 580 real YouTube candidates, plus edge-case strings.
- If the Python matcher changes: `../../apps/spotify-to-youtube/backend/.venv/bin/python tests/golden/gen_golden.py`
  (add `--collect` to refresh the real candidates; needs network), then port the change until the tests pass.
- `combining.ts` is generated by `scripts/gen_combining.py` (Python's combining-class table; JS has no API for it).
- JS `\b`/`\w` are ASCII-only, so the matcher spells out Unicode word boundaries.

## Run
`./instruction.sh setup|test|dev [firefox]|build|zip|lint|e2e`, or directly:
```bash
cd extensions/playlist-bridge
npm install            # .npmrc sets legacy-peer-deps (npm 10 bug with WXT's optional vitest peer)
npm test               # vitest
npm run typecheck
npm run build          # .output/chrome-mv3  → chrome://extensions → Load unpacked
npm run build:firefox  # .output/firefox-mv3 → about:debugging → Load Temporary Add-on (manifest.json)
npm run lint:firefox   # web-ext lint; only React's innerHTML warnings are expected
node scripts/make-icons.mjs   # regenerate icons from the design spec
```

## Decisions
- Five sites, asked for up front: open.spotify.com, api-partner.spotify.com, open.spotifycdn.com, music.youtube.com, www.youtube.com. Reasons in `src/platform/access.ts`.
- The UI is copied, not shared, with the web app. Changes don't propagate.
- Fonts are bundled locally (@fontsource), with no Google Fonts call.
- Firefox MV3 (`--mv3`), minimum Firefox 142 (needed for `data_collection_permissions`).
- "Report a problem" opens a GitHub issue on aditya-n-suman/utilities.
- Distribution: unpacked / self-distributed only.
- Short links (spotify.link, spoti.fi) use *optional* host permissions, requested from the Convert click only when such a link is pasted.
- If paging fails because the query hash is stale: show "Reconnecting…", read the hash from the web player, retry once, then fall back to the `spotify_changed` error (as in the design).
